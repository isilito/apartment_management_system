Database Setup Tutorial

Saraza's Apartment — Property Management System
Version 1.0 · November 2026
For XAMPP (local) and Vercel (online)

The system keeps all of its records in one MySQL/MariaDB database named saraza_apartment. Choose the part that matches what you need:

You want to…FollowTime
Run the system on your own computerPart A: Local database (XAMPP)about 5 minutes
Put the system online with VercelPart B: Cloud database for Vercelabout 15 minutes

Both parts use the same file from the project folder: database/saraza_apartment.sql. It creates the database, all 20 tables, and the demo data (20 units, 17 tenants, payments, maintenance requests, and so on).

Importing the file deletes and recreates the saraza_apartment database. Re-import it any time you want to reset to the demo data, but never on a database with real records you want to keep. See Back up before re-importing at the end of this guide.

Part A: Local database (XAMPP)

1
Start MySQL. Open the XAMPP Control Panel and click Start next to Apache and MySQL. Both rows should turn green.
2
Import the SQL file.

Option 1: phpMyAdmin (easiest)

  1. Go to http://localhost/phpmyadmin.
  2. Click the Import tab at the top. Don't select a database first; the file creates its own.
  3. Under File to import, click Choose File and pick database/saraza_apartment.sql.
  4. Leave the other options at their defaults and click Import (or Go) at the bottom.
  5. You should see "Import has been successfully finished", and saraza_apartment appears in the left sidebar with 20 tables.

Option 2: command line. In PowerShell or Command Prompt, from the project folder:

C:\xampp\mysql\bin\mysql.exe -u root -e "source database/saraza_apartment.sql"

Add -p if your MySQL root user has a password.

3
Check the connection settings. The defaults in api/config.php match a fresh XAMPP install: 
'db_host' => '127.0.0.1',  'db_port' => 3306,
'db_name' => 'saraza_apartment',
'db_user' => 'root',       'db_pass' => '',
If you changed your MySQL password or port, edit those values.
4
Test it. Open http://localhost/saraza/api/health.php (replace saraza with your folder name in htdocs). You should see: 
{"ok":true,"database":"connected","tables":20,"session_store":"files","upload_store":"disk"}
Then open http://localhost/saraza/ and sign in as the administrator. If something is wrong, the health check says what. See Troubleshooting.

Part B: Cloud database for Vercel

Vercel runs the PHP code but has no database of its own, so you need a hosted MySQL. Any MySQL-compatible host that accepts encrypted (TLS) connections from the internet works. Two hosts with free tiers are covered here:

Vercel runs this project's functions in Singapore ("regions": ["sin1"] in vercel.json). A database in the same region keeps pages fast. If yours is elsewhere, change regions to the nearest Vercel region.

B1. Create the database server

Option 1: TiDB Cloud Starter

  1. Sign up at https://tidbcloud.com.
  2. Click Create Cluster and choose Starter (older screens call it Serverless).
  3. Provider AWS, region Singapore (ap-southeast-1). Name it, e.g. saraza, and click Create. It is ready in under a minute.
  4. Open the cluster and click Connect. Choose connection type Public, connect with General.
  5. Click Generate Password and copy it now. It is shown only once.
  6. Note the host, port, username and password (see the table below).

TiDB's certificate is publicly trusted, so you don't need a CA file.

Option 2: Aiven for MySQL

  1. Sign up at https://console.aiven.io.
  2. Create service → MySQL → plan Free → pick the region closest to Singapore that the free plan offers → Create service.
  3. Wait until the status says Running (a few minutes).
  4. On the Overview page, under Connection information, note the host, port, user (avnadmin) and password.
  5. Next to CA certificate, click Download and save it as ca.pem.
  6. Leave Allowed IP addresses at 0.0.0.0/0. Vercel doesn't use fixed IP addresses.

B2. Import the SQL file into the cloud database

The simplest tool is the MySQL client that comes with XAMPP. Open PowerShell in the project folder and run the command for your host. Replace HOST, PORT and USER with your values. It asks for the password.

TiDB Cloud:

C:\xampp\mysql\bin\mysql.exe --host=HOST --port=4000 --user=USER --password `
  --ssl --ssl-verify-server-cert --tls-version=TLSv1.2 `
  -e "source database/saraza_apartment.sql"

--tls-version=TLSv1.2 is needed with XAMPP's MySQL client, which fails TiDB's TLS 1.3 handshake with SEC_E_DECRYPT_FAILURE. The connection is still encrypted and the certificate is still checked.

Aiven (point --ssl-ca at the ca.pem you downloaded):

C:\xampp\mysql\bin\mysql.exe --host=HOST --port=PORT --user=avnadmin --password `
  --ssl-ca=C:\Users\YOU\Downloads\ca.pem --ssl-verify-server-cert `
  -e "source database/saraza_apartment.sql"

In Command Prompt (cmd.exe), put everything on one line and drop the backtick ( ` ). On macOS/Linux, use the mysql client and \ for line breaks.

The import takes 10–60 seconds and prints nothing when it succeeds. To check it:

C:\xampp\mysql\bin\mysql.exe --host=HOST --port=PORT --user=USER --password --ssl --tls-version=TLSv1.2 `
  -e "SELECT COUNT(*) AS units FROM saraza_apartment.units"

It should print 20.

Prefer a GUI? In MySQL Workbench, DBeaver or HeidiSQL, create a connection with the same host, port, user and password (turn on SSL/TLS), then open database/saraza_apartment.sql and run the whole script.

If your host doesn't let you create databases (it gives you one fixed database such as defaultdb):
  1. Make a copy of database/saraza_apartment.sql.
  2. In the copy, delete the DROP DATABASE, CREATE DATABASE and USE lines near the top.
  3. Import the copy into the database you were given (add --database=defaultdb to the command).
  4. In step B3, set SARAZA_DB_NAME to that database's name.
If you already have a database from an older version of the app: don't re-import (that wipes your data). Run database/cloud-tables.sql instead. It only adds the two tables Vercel needs (sessions and uploads) and is safe to run twice: 
C:\xampp\mysql\bin\mysql.exe --host=HOST --port=PORT --user=USER --password --ssl `
  --database=saraza_apartment -e "source database/cloud-tables.sql"

In Vercel, open your project → Settings → Environment Variables and add these. The file .env.example in the project folder has the same list.

B4. Test it

Open https://YOUR-PROJECT.vercel.app/api/health.php. You should see:

{"ok":true,"database":"connected","tables":20,"session_store":"db","upload_store":"db"}

"session_store":"db" and "upload_store":"db" confirm that the app detected Vercel and keeps sign-ins and uploaded files in the database (Vercel's disk is read-only).

Then open the site, sign in as the administrator, and change every demo password right away (Settings → Security). The demo passwords are public in the project's repository.

Troubleshooting

Start with /api/health.php. It names the problem without showing your password or host.

"problem" saysWhat to do
Access deniedWrong user or password. On TiDB the user must include the prefix (3xYz….root). If you lost the password, generate a new one in the Connect dialog and update SARAZA_DB_PASS.
Database not foundThe import didn't run or went into a different database. Re-run B2, or set SARAZA_DB_NAME to the name you used.
Cannot reach the database serverCheck SARAZA_DB_HOST and SARAZA_DB_PORT for typos and extra spaces. Make sure the cluster is running (free tiers can pause) and allows connections from 0.0.0.0/0. On XAMPP, make sure MySQL is started.
TLS problemSet SARAZA_DB_SSL to 1. On Aiven, paste the full CA into SARAZA_DB_SSL_CA_PEM.
Missing tables: sessions, uploadsThe database predates the Vercel version. Run database/cloud-tables.sql (see B2).
Missing tables: … (others)The import stopped partway. Re-run B2 and watch for an error message.
No admin accountThe users table is empty or the admin is disabled. Re-import, or re-enable the admin in the users table.
Database connection failedSomething else. In Vercel, open Logs and look for a line starting with [saraza] health:.

Other common problems

ProblemFix
I changed an environment variable but nothing changed.Redeploy. Variables only apply to new deployments.
The import command says '<' operator is reserved.PowerShell doesn't support < file. Use -e "source database/saraza_apartment.sql" as shown above.
The import says TLS/SSL error … SEC_E_DECRYPT_FAILURE.Add --tls-version=TLSv1.2 to the command (XAMPP's client can't do TiDB's TLS 1.3 handshake).
Pages are slow when XAMPP uses the cloud database.Expected: each query travels to Singapore and back. On Vercel the app and database share a region, so it's fast. Use the local database on your PC.
The import fails with Unknown collation / utf8mb4_unicode_ci.The server is too old. Use MySQL 5.7+, MariaDB 10.3+ or TiDB.
Signing in works, but I'm signed out on the next click (Vercel).The sessions table is missing. The health check shows this; run database/cloud-tables.sql.
Uploads fail with "too large" on Vercel.Expected above 4 MB per file. Vercel rejects request bodies over 4.5 MB.
Opening an .html file by double-clicking shows no data.Pages must be opened through http://localhost/... (or the Vercel address), not as a file:// address.

Back up before re-importing

Before re-importing or making big changes, save a copy of the current data:

# local XAMPP
C:\xampp\mysql\bin\mysqldump.exe -u root saraza_apartment > backup.sql

# cloud (add --ssl-ca=... for Aiven)
C:\xampp\mysql\bin\mysqldump.exe --host=HOST --port=PORT --user=USER --password --ssl `
  --single-transaction saraza_apartment > backup.sql

To restore, import backup.sql the same way as in Part A step 2 or B2 (add --database=saraza_apartment). Don't share or commit backups: they contain tenants' personal details and password hashes. Administrators can also download a JSON export from Settings → Data & backup → Export everything inside the app.
