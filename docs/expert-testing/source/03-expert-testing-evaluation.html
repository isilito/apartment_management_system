#Criterion54321N/A
1. Functional suitability
1Completeness: the system provides all the functions needed to manage units, tenants, payments, maintenance and reports.
2Correctness: balances, late fees, totals and reports are computed correctly.
3Appropriateness: the functions make the property manager's and tenants' tasks easier to complete.
2. Performance efficiency
4Time behaviour: pages, searches and reports load within an acceptable time.
5Resource use: the system runs smoothly in a normal browser without slowing the device down.
6Capacity: the system handles all units, tenants and months of records without slowing down.
3. Compatibility
7Co-existence: the system works properly while other applications and browser tabs are open.
8Interoperability: exported files (CSV, printable pages / PDF) open correctly in other software such as Excel and PDF readers.
4. Usability
9Recognizability: it is easy to tell what the system is for and what each page does.
10Learnability: a new user can learn the main functions without training.
11Operability: forms, buttons and menus are easy to use and control.
12User error protection: the system prevents or clearly explains invalid input (empty fields, duplicates, future dates).
13Interface aesthetics: the interface is pleasing, consistent and well organized.
14Accessibility: the system is usable on phones, tablets and computers, with readable text and keyboard support.
5. Reliability
15Maturity: the system works without errors or crashes during normal use.
16Availability: the system is accessible and working whenever it is needed.
17Fault tolerance: the system keeps working and shows clear messages when something goes wrong (lost connection, invalid file).
18Recoverability: data stays consistent after an interrupted action, and records can be exported or backed up.
6. Security
19Confidentiality: tenants see only their own records; admin pages can't be opened without an admin sign-in.
20Integrity: data can't be changed by unauthorized users.
21Non-repudiation: payments and important actions are recorded with who did them and when (receipts, activity log).
22Accountability: each action can be traced to the account that performed it.
23Authenticity: users are properly verified (passwords, sign-in lockout after failed attempts, auto sign-out).
7. Maintainability (may be rated from the source code and documentation; use N/A if not reviewed)
24Modularity: the system is divided into separate parts that can be changed independently.
25Reusability: shared components (interface, API functions) are reused instead of repeated.
26Analysability: problems are easy to diagnose (clear error messages, logs, health check).
27Modifiability: settings (billing rules, buildings, payment methods) can be changed without changing code.
28Testability: each function has a clear expected result and can be tested.
8. Portability
29Adaptability: the system works across browsers (Chrome, Edge, Firefox, Safari) and screen sizes.
30Installability: the system can be installed or deployed by following the documentation (XAMPP or Vercel).
31Replaceability: the system can replace the current manual or spreadsheet-based process.
